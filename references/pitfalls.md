# 踩坑清单

按"症状 → 根因 → 解法"排。这些都是真金白银花时间换来的，遇到相似症状先查这里。

---

## 渲染与性能

### 全片渲染要 90 分钟

**症状**：22 分钟只跑完 24%，8 并发，CPU 打满。
**根因**：`remotion.config.ts` 里写了 `Config.setChromiumOpenGlRenderer("swangle")`——软件 GL，1080p 画布全靠 CPU 光栅化。绘制代码本身只占 6ms（测过了），瓶颈全在光栅化。
**解法**：改成 `"angle"`（硬件 GL）。同样 40 帧从 64s 降到 25.6s，**全片 90 分钟 → 7.5 分钟**，画面零差异。

> 先把 `swangle` 划掉，这是这个技术栈最大的坑。

### 想测"到底慢在渲染还是慢在绘制"

在 `drawMap` 前后打 `performance.now()`，然后把耗时用 `ctx.fillText` 画到画面角落，渲一张 still 用眼睛读——Remotion 的 `console.log` 在 CLI 里不一定转发出来。

实测结论供参考：地图四层从提交绘制命令到返回只要 6ms。所以"画得慢"的直觉通常是错的，要往光栅化和编码上找。

### `cp -r node_modules` 被 SIGTERM 打断

几万个文件，复制必然超时。用目录联接：

```bash
node -e "require('fs').symlinkSync('<已有工程>/node_modules','node_modules','junction')"
```

### 内存只剩 3.8GB 还能跑 12 并发吗

可以，但要监控。12 并发 × Chromium 实例是这个配置的上限，再往上会因为内存交换而变慢。并发数不要超过物理核心数。

## 地图几何

### 整块大陆被一个矩形盖住

**症状**：规则矩形色块覆盖苏联西部 / 整个屏幕，边缘是笔直的横竖线，不跟随国界。
**根因**（三层，很多人只查到第一层）：
1. `world-atlas` 的 Russia 环跨越 180° 经线（lon 从 −180 到 +179.9），投影后包住半个地球；
2. 用 Sutherland-Hodgman 裁剪 → 算法把多边形沿窗口边界"闭合"，补出一圈贴着窗口边的长边，于是变成整屏矩形；
3. 换成正确算法后仍然有残留，因为 `ctx.clip()` 对 700+ 点的超大路径在 Chrome 里会**静默失效**——形状不生效，也不报错。

**解法**：
- 裁剪改用「保留连续段」算法（`scripts/clip_geo.py`）：只保留落在窗口内的连续点串，段内首尾直连，宁可断开也不造边；
- 填色一律用 `ctx.fill(path, "nonzero")`，**不要用 `ctx.clip()`**；
- 需要"苏联腹地被占"这类效果时，让 Belarus / Ukraine / 波罗的海三国自己切换阵营来表现（它们东界已到 40°E，足够表现「推进至莫斯科以西」），不要硬切大块 Patch。

### 国名对不上，某国永远不变色

`world-atlas` 用 Natural Earth 的写法，不是直觉写法：

```
United Kingdom    Czechia    Bosnia and Herz.    Macedonia
United States of America     Russia    Serbia    Kosovo
```

写立场表之前先 dump 一遍 key，逐个核对：

```bash
node -e "console.log(Object.keys(require('./src/europe-clip.json').countries).sort().join(' | '))"
```

### 国界看着发糊 / 箭头外发光变硬

`shadowBlur` 换宽描边之后要**控制两层**：外层 `lineWidth` 5.5、alpha 0.30 当光晕，内层 1.6、alpha 0.95 当实线。只留一层就会显得"硬"。箭头外发光同理（`w*0.55` / alpha 0.22）。

### 手绘的势力边界"有棱有角"，像用尺子画的行政图

**症状**：观众直接说"边界太假""有棱有角""不像历史疆界"。
**根因**：势力区是十几二十个手写顶点的多边形，两点之间是直线段；放大后每个拐点都是硬角。
**解法**：两层处理，都不要省。

```ts
// 1) 闭合 Catmull-Rom 过点插值：折线变曲线，尖角消失
const catmull = (pts, per = 12) => { /* 每段插 per 个点，端点用镜像虚点 */ };

// 2) 沿法线叠三层不同频率的正弦扰动：远看是弧，近看有细碎起伏
//    频率取 3 / 7 / 13，幅度按区域尺度给（大区大起伏），用 id 做种子保证可复现
const hash01 = (s) => { /* FNV-1a → 0..1，当扰动相位种子 */ };
```

古代部族的疆界是被山脊、河道、林线切出来的软边界，**没有一条是直线**。这一层做完，同样的多边形立刻从"行政图"变成"地形图"。

### 高倍机位（zoom > 6）把地图画成一堵色墙

**症状**：推近到 10~24 倍时，势力多边形铺满整屏，边框跑出画外，只剩一块纯红。
**根因**：势力区是"区域级"的面，放大 20 倍后画面里根本没有它的边界。
**解法**：这一档**不画地图**，改画符号层——同心圆环（范围/射程）、楔形箭头（方向）、虚线（航线）、单位图标（舰船/军团）。地图只留极暗的底和一条海岸线做锚定。详见 `SKILL.md` 的"战术示意图"。

### 陆地被填成一整块矩形 / 海被填成陆地

**根因**：`extract_geo --mode land` 拿到的陆地是**一整个环**（欧亚非连在一起、跨 ±180），平面多边形里它不是简单多边形，裁剪时首尾直连会造出横贯全图的假边，把利古里亚海填成陆地。
**解法**：**填充和描边用两份数据**。

```bash
# 填充：各国 union 后再裁窗（国家是天然小闭合环，内部国界被 union 合并掉）
node scripts/extract_geo.js --mode countries --win -10 32 30 51 --out src/borders.json
node scripts/clip_geo.js --src src/borders.json --win -10 32 30 51 --out src/land-win.json
# 描边：只描海岸线，避免现代国界在地图上发光
node scripts/extract_geo.js --mode land --win -10 32 30 51 --out src/coast-win.json
```

`fill(landPath, "evenodd")` 用 union 结果，`stroke(coastPath)` 用原始陆地环，两者都不走 Chaikin 切角（`--tol 0.0012` 已经足够密）。

### 势力区多边形不能"等分画一圈"

**症状**：全图镜头里，东欧草原上浮着一块边缘极光滑的灰斑，像有人用椭圆工具画了个圈；放大看它的描边是一条完整闭合的曲线，完全没有海岸线的锯齿。
**根因**：那个 region 的 `poly` 是把一个包围盒按角度等分取 21 个点写出来的——**形状本身就是椭圆**。更糟的是它整体落在陆地上，`clip(land)` 一点作用都没有（陆地裁剪只能收海岸边，收不了内陆边界）。
**判断方法**：写个脚本把每个 region 的多边形栅格化，逐点问"这里是不是陆地"，输出"水面占比"和"落水顶点"。**水面占比 0% 的区域，它的轮廓就完全由自己那圈点决定**，必须画得像地理；占比高的（岛屿）反而是靠 `clip(land)` 收边，点粗一点没关系。
**解法**：沿真实地物密集采样。草原区就按「波罗的海岸 → 第聂伯河 → 黑海北岸 → 多瑙河口 → 喀尔巴阡山脊」一路走，50 个点起步，每段都带注释说明跟的是哪条河/哪道山。

### 区域镜头的机位方向：越拉近越像色块

**症状**：想把"某块地被擦掉"的边界看清楚，于是把机位从 2.4 推到 1.75、再推到 1.30，结果一次比一次糟——屏幕上只剩两大片颜色和一道弧线，完全读不出地理。
**根因**：区域多边形的边界本来就是**简化过的**。拉近等于把简化误差放大到全屏，边界必然呈弧；同时海岸线、河流、邻国都被挤出画框，观众失去了判断"这是哪儿"的参照。
**解法**：**往后退**。全图 0.35、区域 0.9–1.1、特写 1.9–3.0。要让"红在缩"这件事成立，得同时看见高卢（红）、日耳曼（灰）、意大利——1.02 就够；推到 1.3 反而什么都说明不了。

## 势力推进（波前）

这一节的六条是同一个系统里连锁出现的，改动时要么全做，要么别动。

> **不要从头写。** `assets/template/src/front-push.ts` 是这套机制的成品，已验证（同事件共线、圆心就近、世界坐标裁剪、锋线起伏、三层辉光）。新工程直接拷进去，只需传入 `regions` / `order` / `stateAt` / `proj` 四个参数。下面六条讲的是"它为什么长这样"，改它之前再看。

### 边界"重叠"：红蓝之间有一条既红又蓝的紫带

**症状**：撤退/争夺的镜头里，红蓝交界不是一条线，而是两三条互不重合的斜边；交界处颜色发紫，像两块半透明色布叠着。
**根因**：**波前按区域各自建**。每个 `region` 自带一个 `dir`，同一次东征里亚美尼亚从南往北推、美索不达米亚从西往东推，两条锋线根本不重合。红的一侧退到 A 线、蓝的一侧推进到 B 线，A 与 B 之间就是那块"既红又蓝"的带子。
**解法**：**按事件建锋线，不按区域建**。把所有 region 的 key 按时间聚类（间隔 < 4.2 秒算同一次事件），同一事件的所有区域共用一个圆心、一个半径。红用 `side=-1`、蓝用 `side=+1`，天然互补。

```ts
// 事件表：同一时刻变色的区域共用一条锋线
for (const g of groups) {           // g = 同一事件里的 (region, keyTime)
  const pts = g.flatMap(q => regionRaw(q.r));
  const lead = /* 组内 to 阵营里 SIDE_ORDER 最高的那个 */;
  const f = { ox, oy, ax, ay, qmin, qmax };   // 圆心 / 轴向 / 径向区间
  for (const q of g) evFront.set(`${q.r.id}@${q.t}`, f);
}
```

### 波前之外的地图"缺了一大块"

**症状**：变色进行到一半时，波前另一侧不是旧领土的颜色，而是一片压暗的陆地色，看起来像地图被挖掉一角。
**根因**：`clipSide()` 里 `translate(圆心) + rotate(轴向)` 之后再 clip，但紧接着的 `fill(regionPath)` 用的还是**世界坐标**。两者差一个平移加旋转，整块地被画到画面外。
**解法**：裁剪路径一律**在世界坐标里手算**，绝不改当前变换：

```ts
const W = (x: number, t: number): [number, number] => [
  f.ox + f.ax * x - f.ay * t,     // 轴向分量 + 垂直分量
  f.oy + f.ay * x + f.ax * t,
];
```

### 一道巨大的圆弧横穿领土

**症状**：只是巴尔干一小块地在易主，屏幕上却有一道半径几十像素级的大弧从意大利横切到黑海，弧两侧红色深浅不同。
**根因**：圆心取了**整个帝国的质心**（罗马的质心在意大利甚至高卢）。锋线从那里扩散到巴尔干时半径上千，落到屏幕上就是一条横穿全图的弧。
**解法**：圆心只取**推进方离战场最近的那几块领土**的质心（按到事件质心的距离排序，取前 3 块按顶点数加权）。

### 同一阵营内部浮出一堆细裂纹

**症状**：红区里有好几条细弧线，绕过整块领土，像釉裂。
**根因**：逐区域 `stroke` 边界，再用自家 `fill` 擦内侧。`fill` 只擦得掉线的**内半宽**，外半宽留在外面；接缝两侧各留半条，叠起来正好是一条完整的线。
**解法**：**从阵营并集剪影取外轮廓**，内部物理上不可能有线：

```ts
// rim：模糊 − 自减 = 只剩外沿
e.filter = `blur(${r}px)`;
e.drawImage(maskCv, 0, 0);
e.filter = "none";
e.globalCompositeOperation = "destination-out";
e.drawImage(maskCv, 0, 0);          // 挖掉本体，留下外圈
e.globalCompositeOperation = "source-in";
e.fillStyle = EDGE[pol]; e.fillRect(0, 0, W, H);
```
外晕半径 `10 / cam.zoom`（上限 15）、细边 `2.4 / cam.zoom`（上限 3.4），两层足够。

### 两块地之间出现一个"四角星"暗斑

**症状**：两个相邻区域的交界处有一块暗色星形/菱形，比接缝本身还显眼。
**根因**：两块的多边形之间留了 0.3~0.7° 的缝。缝里的地不属于任何势力，被"无主地压暗"涂成深色；而两侧边界都被 Catmull 平滑过，缝的形状就变成不规则星形。
**解法**：相邻区域的边界**故意重叠 0.3~0.5°**（更低的那个优先级会被更高的挖掉，重叠区看不出来）。宁可重叠，不可留缝。

### 领土是"啪一下"整块变色的

**症状**：观众说"没有推进感，是直接加进来的"。
**根因**：`polityAt` 的 `dur` 只有 1.15 秒（不到两个拍子），而且用 `easeOut`——90% 的位移发生在头几帧。
**解法**：`dur = 3.0`（约 7 拍，一个乐句），缓动换 `easeInOut`。再给锋线画一条亮线（宽晕 + 主体 + 白芯三层），推进才成为一个动作。

```ts
// 旧色残块的浓度要随波前衰减
// 固定 0.46 时，p≈0 那一瞬旧主只给半色、新主还没到，
// 整块地会突然暗下去，像无人区。
overlay(o, cv, REMNANT_A[pol] + (FILL_A[pol] - REMNANT_A[pol]) * (1 - pAvg));
```

### 锋线断成几截

**症状**：锋线只在某个角上亮一小段，其余部分没有。
**根因**：两个原因叠加。① 按区域分别画，各自被自己的多边形裁断；② 用 `clipSide(side=1)` 裁圆，线正好躺在裁剪边界上，外侧半宽被切掉。
**解法**：按「事件 + 进度」去重，一次画一整条，并且**只裁到该事件的地块并集**（`Path2D.addPath` 累加），不裁圆。

### 波前一上线，先跑这六项自检

渲染之前逐条对，任何一条不过就别开全片（全片一次 8 分钟，返工不起）。

| # | 检查 | 不过的表现 |
|---|---|---|
| 1 | 同一次事件的所有地块，`front` 是**同一个对象引用** | 交界处出现"既红又蓝"的紫带 / 三条互不重合的斜边 |
| 2 | 波前之外的地仍然有归属色 | 地图像被挖掉一角，只剩压暗的陆地色 |
| 3 | 阵营内部没有细弧线 | 红区里像釉裂一样爬着几条曲线 |
| 4 | 相邻地块之间没有暗色星形/菱形 | 交界处浮出一个比接缝还显眼的暗斑 |
| 5 | 逐帧看 0→100%，颜色是**连续扫过去**的 | 某一帧整块地突然变色（`dur` 太短或 `easeOut`） |
| 6 | 锋线是一条连续的亮线，有白芯 | 只剩几个孤立的亮弧 / 一条发丝 |

单帧验证用 `remotion still`，连拍三帧（推进前 1/4、中、后 1/4）就能看出是不是"扫过去"的：

## 边界清晰度（用户原话：「国家的边界要清晰」）

七条，按"从画面到代码"的顺序排。改造时的正确目标数值见 `visual-system.md`
「边界必须清晰：这是可量化的」。

### 边界"看不见"：填色把线淹了

**症状**：远看是一块完整的红色，凑近才有一条模糊的边；缩略图里根本没有边界。
**根因**：填色太亮。实测旧参数 `FILL_A=0.88 × rgb(180,26,38)` 叠在蓝灰陆地上
得到 `rgb(164,32,47)`，而边界线只有 `rgb(177,74,87)` —— **亮度比 1.1**。
参考片是 `76 : 247`，比值 3.2。
**解法**：填色压到 `rgb(98,19,12) @ 0.88`（实测 93,25,24），线提到 `rgb(255,146,134)`。
**不要靠降 alpha 压暗**：底色会从下面透上来抬高 B 通道，红色变粉紫（见下条）。

### 降 alpha 会把红色变成粉紫

**症状**：填色压暗之后，红色偏紫、发粉，和参考片那种暖暗红完全不同。
**根因**：陆地底是 `rgb(61,83,121)`。`alpha=0.58` 时剩 42% 的底色透上来，
B 通道被抬高约 30 点 → `(127,47,69)`。
**解法**：**更暗的色 + 更高的浓度**。`0.88 × rgb(98,19,12)` ≈ `(93,25,24)`，
既压暗又不污染色相。

### blur 出来的环只有 0.5 alpha，是"雾"不是"线"

**症状**：线看着发虚、发雾，放大看没有边界感。
**根因**：`filter: blur(r)` 再 `destination-out` 本体，得到的是高斯截面的环——
边界处的峰值只有约 0.5（核一半在内一半在外）。
**解法**：**同一张模糊图叠 5 次**（alpha → 0.97），横截面才接近方波。
`for (let k=0;k<boost;k++) e.drawImage(mk,0,0)`，`boost` 作为 rim 的参数。

### 外发光被陆地裁剪切掉

**症状**：领土边缘像用刀裁的硬边，海面上没有任何光。
**根因**：`drawPolities` 开头 `o.clip(getLandPath())` 包住了整个函数，
贴边界层也在里面，光一越过海岸线就被切。
**解法**：把「贴边界层」挪到 `o.restore()` **之后**；波前亮线单独再 `clip(land)` 一次。
参考片的光恰恰是"从海岸漫到海上"的，这一层必须放出来。

### `clip(land)` 套在描边上 → 线直接消失

**症状**：改用 `stroke(区域路径)` + 挖本体之后，边界几乎没了，只剩 1px 残渣。
**根因**：描边 5px 有一半在海里，`clip(land)` 先切掉那半；接着
`destination-out` 本体又把剩下那半挖光——两次裁剪叠加正好互相抵消。
**解法**：**描边时不要 clip 到陆地**。剪影本身已经裁过陆地，它的边界就是海岸线；
描边挖本体后剩下的外侧半圈正好落在海面上，就是想要的效果。

### 同阵营两块地之间出现一条灰黑色的"沟"

**症状**：一整片蓝色中间有条暗带贯穿，两侧各有一条亮边，像地图裂了。
**根因**：相邻区域的多边形**没接上**。差 0.13~0.26° 就够——在这个机位下是 20~40px。
缝里的地不属于任何一方，被「无主地压暗」涂成灰黑。
**解法**：**故意重叠 2~3°，不要"刚好相切"**。重叠区由 `SIDE_ORDER` 挖洞处理
（罗马在时挖掉帕提亚），同阵营时并集无缝。
按"把两条平滑曲线调到刚好重合"是徒劳的——插值一算就差 0.2°。

> 反例记录：这一条我调了四轮坐标（47.9 → 48.4 → 47.0 → 46.5）都没消掉。
> 每次都在"再挪 0.5° 就好"上打转，正确做法是一次性重叠 2° 以上。

### 区域多边形是"月牙"，特写下像融蜡

**症状**：某块地只有十几个点、形状规整，拉近之后是一摊光滑的色块，
完全不像地理；边缘是巨大圆弧。
**根因**：点太少 + 范围写小了。E4 的帕提亚只有 19 个点、`47.6~55.6E`，
而它历史上从幼发拉底铺到印度河——东边一半根本没人认领，
被压暗成黑带，观众读成"数据缺失"。
**解法**：按真实地理骨架重画（河流 / 山脉 / 海岸），点数 25+，
范围一直画到窗口之外（`62E`）。**宁可画出窗口，也不要在窗口内被切断**——
被切断的边缘在镜头里就是一段圆弧。

## Canvas 与坐标

### 第一帧标题跑到屏幕左上角

**根因**：地图层调过 `applyCam`，变换矩阵还带着 cam 的平移缩放；之后画屏幕坐标的 HUD 就被一起带偏了。
**解法**：每个 HUD / 屏幕空间函数**开头 `resetT(ctx)`**。这条要当成硬规矩，新写的函数照做。

### 事件插图完全看不见，日志却说加载成功

**症状**：`console.log` 打出 `[img ok] kiev 1536 1024`，但画面上连一块暗影都没有。标题正常显示，所以不像"整镜没画"。
**根因**：`drawMap()` 结尾停在 `applyCam` 留下的变换矩阵上（`cam.zoom` 缩放 + 平移）。`drawNodePic` 若漏了复位，插图会按 cam 缩放被画到画布范围之外——画了，但画在屏幕外。
**解法**：`ctx.save()` 之后第一件事 `ctx.setTransform(1, 0, 0, 1, 0, 0)`。**这条和"第一帧标题跑到左上角"是同一个根因**，凡是在 `drawMap` 之后画屏幕坐标的东西，都必须先复位。

### 用 build 目录渲染时插图全部消失

**根因**：`npx remotion bundle --out=build` **不会**复制 `public/`。图片 `onerror` 后静默跳过，画面上什么都不缺，就是没有图。
**解法**：

```bash
rm -rf build                                   # 目录已存在会报 EISDIR
npx remotion bundle --out=build
mkdir -p build/img build/audio
cp public/img/*.png build/img/
cp public/audio/score.wav build/audio/
```

### 插图看着像贴了张矩形海报

**根因**：直接把 PNG `drawImage` 上去，四边是硬边。
**解法**：离屏 canvas 用 `destination-in` + 四边线性渐变做羽化（横向 0.26/0.74、纵向 0.24/0.76），再叠一层上下压暗 + 扫描网纹。代码见 `assets/template/src/assets.ts`。

### 插图底部有一条奇怪的浅色横条

**根因**：生成器压的水印。提示词写了 `no watermark` 也常出现。
**解法**：取源图时只画到 `height * 0.93`，剩下 7% 直接丢掉。

### 城市战术图几乎全空，只有一个中心点

**根因**：`drawCityBoard` 里 `applyCam` 之后没 `resetT`，网格和圆点被画到了坐标范围外。
**解法**：战术图**不要用地图坐标画网格**，改用屏幕尺度：52px 街区网格 + 贝塞尔河流，然后 `drawDots / drawRing / drawPlane / drawExplosion / drawBracket` 全部先 `resetT`。

### 箭头看起来像一根粗线，不像军事推演箭头

**根因**：只 `lineTo` 画了一条折线加 `lineWidth`。
**解法**：带状箭身——沿折线做法向 offset 生成闭合轮廓（`wid = w/2*0.7`），末端接三角箭头（`bw = w*1.02`），中轴再画一条亮线提精神。

## 视觉

### 占领区糊成一片红斑，看不出层次

**解法**：层次靠**轮廓亮度**分，不靠填色浓度分。填色压到 0.14（本土 0.26），描边分三档（本土 1.9px/α1.0、占领 1.5px/α0.85、争议 1.2px 虚线 α0.5）。再给本土加一层外发光（宽描边 `lineWidth 7` / α0.26），层次立刻出来。把填色堆到 0.4 以上只会把海岸线一起糊掉。

### 地图上的地名是拉丁字母 / 英文字幕

**症状**："各地区的名字要用中文"。
**根因**：地理数据里自带 `name` 字段（`LATIUM`、`Etruria`），直接拿来画了。
**解法**：**地名表一律自己写**，不读数据里的 name。每个地名配一个落点经纬度，并且必须做**避让**——标签之间、标签与城市点之间设最小间距，依次试 `0 / -30 / 30 / -60 / 60 / -92` 的偏移，全都撞就不画（宁缺勿叠）。标签用**屏幕坐标固定字号**绘制，世界坐标会随 zoom 放大成巨字。

### 爆炸像一团模糊橙光

**解法**：白闪（`p < 0.11` 全屏白）+ 6 段径向渐变火球（`r = (30 + 520*grow) * scale`）+ 4 层冲击波环 + 34 条带 jitter 的放射线。缺任何一层都会"软"。

### 标题副行贴着红框底边

**解法**：副标题 y 从 `size*0.95` 改为 `box ? size*1.1 : size*0.95`，同时把框的 `shadowBlur` 从 30 降到 24，再给副标题加暗色描边（`rgba(2,4,10,0.9)` / blur 16）。

### 终局"金色"发浊、像灰褐

**根因**：在深蓝陆地（`#141d30`）上直接叠金色，混出来是浊褐色。
**解法**：先用**暖色陆地打底**（`drawBG(ctx, t, warm)` 的 `warm` 参数），再叠金色，得到的是"青铜浮雕匾"的质感。

## 音频

### numpy / librosa 装不上

`ERROR: Could not find a version that satisfies the requirement numpy`——环境里没有可用的 wheel 源。

**解法**：全部改用 Python 标准库 `array` + `math` + `struct` 手写。`scripts/analyze_beats.py`（RMS 包络 → 对数 onset → 浮点插值自相关测 BPM → 相位扫描）和 `scripts/build_audio.py`（下扫正弦 impact、噪声低通 whoosh、riser、boom）都是纯标准库，无需任何依赖。

> 同一个环境里 **pillow 也装不上**（`No matching distribution found`）。要做像素采样就退回 ffmpeg（`crop=1:1` + `od`），要做栅格化就用纯 Python 射线法——都够用，不要在这上面耗时间。


### 卡点音效听不出来 / 感觉提前了

先确认**切点真的落在拍格上**，而不是靠耳朵找的近似值。打印 `(t - (PH + k*BEAT)) * 1000`，超过 ±10ms 就应该修。

### 叠加多层音效后爆音

采样叠加后峰值会超过 32767 硬削波。`build_audio.py` 最后统计峰值并按 `limit: 31000` 等比软限幅——不要用 `Math.min(32767, x)` 直接削。

## 工作方法

### 千万别用肉眼读缩略图判断"陆地在哪、海在哪"

**症状**：反复怀疑"陆地没填上""颜色反了"，改了两轮代码，最后发现渲染一直是对的。
**根因**：暗场风格里海是近黑（`#04070e`）、陆地是蓝灰（`#35486b`），缩略图 + 暗角 + 屏幕色偏之后，**两者的相对明度极容易看反**。看反了就会把乌黑的亚得里亚海当成意大利半岛。
**解法**：任何"陆海/覆盖范围"的判断都走**像素采样**，不走眼睛。

```bash
# 单点取色（不需要 PIL）
ffmpeg -v error -i out/f.png -vf "crop=1:1:1101:804" -f rawvideo -pix_fmt rgb24 - | od -An -tu1

# 想一次看一片：把帧降到 64×36 打成字符地图
ffmpeg -v error -i out/f.png -vf scale=64:36 -f rawvideo -pix_fmt rgb24 - > /tmp/s.r
# 再按 RGB 阈值分档打印 '.' / '#' / ' '

# 想确认"数据本身对不对"（排除渲染层）：把 src/land-win.json 在 Python 里栅格化，
# 用射线法逐格判断内外，打成 ASCII 图，和渲染帧并排比
```

两条经验：**先验数据、再验渲染**，不要一上来就改绘制代码；判断"某个经纬度在不在陆地"用点在多边形内测试，比看画面可靠一万倍。

### 别用图片比对工具判断"画面有没有变"

多次遇到工具返回 `[Image unchanged]` 就误判成"改了没生效"，反复改代码白折腾。改成**直接看画面**：`ViewImage` 提问具体问题（"边界线是否模糊""有没有笔直的矩形边"），或者裁切放大局部再看。

> 补充：`[Image unchanged]` 有时是真的画质相同（比如只改了另一支分支的代码）。遇到它先核对"这次改动是否真的影响这一帧"，再决定要不要继续查。


### 抽查帧的时间点要精确

抽样早 0.5s 会看到"空镜"，误判成 bug。比如柏林插旗那一镜，红旗是 `132.0s` 才弹出，取 `131.5s` 只能看到空网格。**抽帧前先看代码里元素的入场时间。**

### 别迁就素材长度

原始素材 161.5s 不代表片子要 161.5s。按音乐结构（drop / breakdown / 最响段）重新裁到 150.41s，剧情和音乐才对得上。**裁音乐，不是拉长时间轴。**

## 势力区与轮廓（E2《海与盐》踩出来的四条）

### 半透明填色逐块画 → 相邻边线叠成一道"亮缝"

**症状**：势力区内部浮出弯弯曲曲的亮线，像画错了的多边形，放大 2 倍后每块区域都被自己的轮廓描了一圈。
**根因**：为了盖住相邻多边形之间的 1~2px 缝，`fill()` 之后又用**同一个半透明颜色** `stroke()` 了一遍。缝是盖住了，但描边叠在填色上 → 0.29 叠 0.29 ≈ 0.5，整条边界比内部亮一倍。
**解法**：**先做不透明剪影，再整体上色**。

```
m.clearRect() → applyCam → clip(陆地)
for 每块区域: fillStyle="#fff"; fill(path); stroke(path)   // 白色叠白色，缝没了也不变亮
m.setTransform(1,0,0,1,0,0)                                 // ★ 见下一条
m.globalCompositeOperation="source-in"; fillRect(0,0,W,H)   // 整体着色
o.globalAlpha = 0.235; o.drawImage(m, 0, 0)                 // 整体降透明度
```

剪影内部浓度完全均匀，只剩一条干净的外轮廓。

### `source-in` 上色前必须把变换归位

上面那段如果漏了 `setTransform(1,0,0,1,0,0)`，`fillRect(0,0,W,H)` 是在**世界变换**下画的，覆盖不到整张画布；`source-in` 只保留被覆盖到的部分，其余剪影直接消失。
**症状很好认**：只有一小块势力区还在，别的阵营整片不见了，但代码逻辑看起来完全正常。

### 轮廓要"只留并集外沿"，不是"描每块区域的边"

同一个问题换个场景：跨阵营的边界要亮，同阵营内部不该有线。
**解法**：边线画在**独立图层**上，然后拿本阵营**所有区域**去做 `destination-out` 填充——内部那条边两侧各被擦掉一半，彻底消失；并集外沿只剩外面半个线宽，成了干净的亮边。宽晕 + 主边 + 细白芯三层都用同一套擦除，效果是"发光轮廓"而不是"色块贴纸"。

### 箭头宽度是世界单位，不是像素

`drawArrow(..., w)` 的 `w` 要乘机位倍率才等于屏幕像素：同一个 `w=26` 在 165% 机位是 43px、280% 机位是 73px——直接变成一道光柱。
**解法**：在 `drawArrow` 内部统一乘一个全局系数（`ARROW_SCALE = 0.6`），并让 `head` 同步缩放，否则箭头会被拉成又细又长的针。片子里箭头是**注记**，不能抢地图的戏。

### 陆地底色：不要凭感觉调，抄上一集的实测值

这条被我自己写错过一次，值得单独记：E1 的陆地是**亮蓝灰**（`#3d5379 / #35486b / #2b3a58`，实测约 `rgb(49,65,96)`），海才是近黑（`rgb(12,17,25)`）。我曾把视频帧里的 `(12,17,25)` 当成陆地、把 `(49,65,96)` 当成海，于是整个第二集把地压到 `#22304c`，成品比第一集更黑更闷，用户一眼看出"画风不统一"。

**做法**：新一集先 `ffmpeg -ss N -i 上一集成片.mp4` 抽三帧，用 `crop=2:2:x:y` + `od` 采样 **确认哪个坐标是陆地**（配合陆地矢量的边界坐标核对），再把数值写进新一集的 `drawLand`。同一个系列里，这组数值就是视觉契约，不要重新发明。

### 两块势力区在几何上真的重叠 → 同一片地既红又金

手绘的 21 个区域多边形必然互相咬合（E2 里 16 对重叠，最大 1.5 平方度）。半透明填色一叠就双倍浓度，边界也会横穿别人的地盘——观众看到的是"领土重叠"。

**解法（坎儿在第二步）：**
1. 每个阵营一张不透明白色剪影，同阵营区域先并集（白色叠白色不加深）；
2. 按优先级互相**挖洞**（`destination-out` 画高优先级那张），同一片地只留一个归属；
3. 填色时各阵营剪影已互不相交，不会再叠出深浅。

⚠️ 第三步画边界时**不能用 `destination-in` 剪影**：那样边界确实只落在自家地盘里，但同阵营内部那道线会全冒出来（马其顿和希腊同色，交界成了一条穿过金区的大弧）。要的是"边线画一层 → 用自家所有区域 `destination-out` 擦掉内侧"，只留并集外沿。代价是跨阵营重叠处可能残留半条线，**所以第 2 步的挖洞不能省**。

> **"边界重叠"有两个完全不同的病根，别混。**
> 本节这条是**静态**的：两块地在几何上压着，画出来一块地两个归属 → 用挖洞解决。
> 还有一种是**动态**的：变色过程中两条锋线错位，交界处形成一条"既红又蓝"的紫带 → 见「势力推进（波前）」。E4 里用户报的"边界还是有重叠"，主因是后者；只修前者完全没用。

### 事件插图别做"浮在中间的海报"

图放正中、四边均匀羽化，看起来像贴了一张纸。让插图**偏心**（右侧压到画框边附近）画面立刻从"贴纸"变成"版式"。

⚠️ 但"偏心"不等于"出血切主体"。E4 抄了旧版 `(1480, 780)` 直接照搬，图宽 960 时右边到 1960、下面到 1140，右下两角全出画，看起来就是"图被切坏了"。两条界限：

- **要出血，必须出血在可裁的地方**：边缘是雾、地面、烟雾、天空——切掉不丢信息；
- **主体必须在画框内**：拱门、人群、圣殿这类"要看的东西"不能压到边线上。

写坐标前先算包围盒，见「插图中心不要凭感觉写坐标」。图后面要垫一层略大于图的径向暗影，否则羽化区会把下面的势力红透上来，版画糊成一片（半径要等于渐变末端，见下条）。

## 事件插图（做旧版画）

### 羽化之后不能再叠"不透明边缘"的压暗层

插图本身用 `destination-in` 渐变羽化到透明，如果再用一个 `fillRect` 铺上下压暗、且渐变两端是不透明色（`rgba(4,3,9,0.96)`），就会在羽化之外**贴出一圈硬矩形边**——瞬间从"从暗场里长出来"退回"贴了张海报"。
**解法**：压暗层的渐变**两端必须是 0 alpha**，只压内部（`0 → 0, 0.24 → 0.34, 0.82 → 0.38, 1 → 0`）。想加网纹同理，别铺满整块矩形。

### 生成器水印

右下角固定压一条"AI生成"。裁剪时按 `crop=1229:922:153:0`（1536×1024 先切掉底部 10%，再左右各切 153px 收成 4:3）一刀解决，别在合成里靠 `height*0.9` 硬压——那会把画面纵向拉扁。

### 插图中心不要凭感觉写坐标（E4《帝国之血》返工）

**症状**：插图只露出左上四分之一，右下两角全在画框外，看起来像"图被切了"而不是"刻意排的"。
**根因**：`drawNodePic(ctx, name, 1480, 780, 960, …, 3/4)` —— 中心 x=1480、y=780，宽 960、高 720，右边界到 1960（画面 1920），下边界到 1140（画面 1080）。
**解法**：先算包围盒再写数。1920×1080 下"居中偏右、完整入画"的稳妥组合是 `(1330, 668, 900, 9/16)` → `x 880–1780, y 415–921`，左右各留 140px 给羽化。
另外**插图镜不要再画图例**：`drawLegend` 在右下角，正好和插图撞；规范里写的"只留标题 + 插图"不是修辞。

### 加了径向暗底，椭圆半径必须等于渐变末端半径

**症状**：插图外面套着一圈明显的深色椭圆，边缘是硬的，像贴纸。
**根因**：暗底用 `ctx.ellipse(cx, cy, w*0.62, h*0.62)` 裁切，但渐变半径是 `max(w,h)*0.56`。16:9 时 `h*0.62` 远小于 `max(w,h)*0.56`，渐变还没走到 0 就被椭圆切掉，露出一圈半透明硬边。
**解法**：`ctx.ellipse(cx, cy, max(w,h)*0.60, max(w,h)*0.60, …)`，和渐变末端对齐；渐变中途的落差也要拉平（`0.90 / 0.80 / 0.46 / 0`），否则四角仍然偏亮。

### 羽化宽度决定"版画会不会被地图染色"

**症状**：版画的左侧被染成粉红、右侧被染成深蓝，棕榈树看得见但整个画面脏了。
**根因**：四边羽化 30%（`0.3 → 1`），羽化区内插图只有部分不透明度，下面的势力填色直接透上来。
**解法**：羽化收到 **19%**（`0.19 → 1` / `0.18 → 1`），同时把暗底的不透明度提到 0.80 以上。两件事要一起做——只收窄羽化，中段仍然透；只加暗底，边缘仍然有红蓝晕。

### JS 的 `%` 保留符号，伪随机取 [0,1) 会取到负数

**症状**：整片渲到第 3669 帧崩掉，`IndexSizeError: Failed to execute 'arc': The radius provided (-0.00570252) is negative.`；可前面抽了十几个关键帧都好好的。
**根因**：撒盐/火星这类粒子用 `(Math.sin(i * 12.9898) * 43758.5453) % 1` 做伪随机。JS 的 `%` **保留被除数符号**，结果落在 `(-1, 1)`；半径 `1.1 + r2 * 1.2` 一旦 `r2 < -0.9167` 就变负，`ctx.arc()` 直接抛异常。粒子只在特定帧、特定 `i` 上才命中，所以抽帧验收根本发现不了。
**解法**：`Math.abs(Math.sin(...) * 43758.5453) % 1`，或者干脆写 `const fract = (v) => v - Math.floor(v)`。凡是拿来当**半径 / 透明度 / 索引**的伪随机，一律先确认值域。

> 由此得一条硬规矩：**抽帧只能证明"这几帧没问题"，不能证明"这片能渲完"**。交付前必须整片渲一遍；报错帧号比任何抽帧都准。

## 势力色撞上陆地底色（E2 第二轮返工）

### 症状：观众把「没被占领的地」读成「某个国家」

画面里意大利东岸浮出一条蓝带，和迦太基的蓝几乎一样，播出后直接被问"这蓝色区域代表什么"。
**根因是两层叠加**：
1. 陆底色是 E1 传下来的蓝灰 `#3d5379`（经暗角实测 `(41,67,109)`）；
2. 迦太基填色 `rgb(34,74,140) @0.84` 叠在同一块底上算出来是 `(38,75,137)`。
两者蓝通道只差 28，人眼分不开。而那块"蓝带"其实**根本没被任何 region 覆盖**——是没主的地露了底色。

**三条一起改，缺一不可**：
- **无主地必须显式压暗**。陆地先铺一层 `rgba(0,0,0,0.34)` 黑纱，再把各家剪影 `destination-out` 挖回去。有主的地保留原明度，无主地退到接近海面——画面里只有势力色是有颜色的。压到 0.62 会整片黑到读不出地形轮廓，0.34 是"仍能看出陆地形状、但明显不是国家"的那一档。
- **势力色要拉开色相，不要只调明度**。`rgb(12,58,176)` 这种宝蓝和灰蓝差 80 多个蓝阶，一眼可分；之前试过压深到 `rgb(14,38,112)`，反而又滑回灰蓝带。
- **凡是画面上会出现的地，必须有人认领**。意大利东岸（皮凯努姆/马尔凯）漏了区域，就出这条蓝带。补 region 比事后调色更治本。

### 并行坑：残块和并集剪影共用 canvas，填色只剩碎片

把「建并集剪影」提前到「画旧色残块」之前，残块会**覆盖**同一张 `getMaskCv(pol)` 画布，
后面填色时拿到的就不是并集而是残块。
**症状**：迦太基的蓝几乎消失，只剩几块零散碎片，而代码逻辑看起来完全正常——因为每个函数单独都是对的。
**规矩**：一个 canvas 只承担一种图形。残块单独一张 `getRemCv(pol)`。
