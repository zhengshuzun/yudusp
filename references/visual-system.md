# 视觉系统

这是"沙盘"系列的统一外观。换题材可以换地图、换事件、换阵营，但下面这套视觉规则应当保持——它才是观众认出"同一个系列"的东西。

---

## 一、配色：锁死，不要换

红 = 扩张方（轴心 / 入侵者），蓝金 = 抵抗与反攻方（同盟）。这一条是整片最核心的视觉记忆点，任何一镜都不许为了"好看"临时改色。

```ts
// palette.ts
export const C = {
  void0: "#03050a", bg0: "#060a14", bg1: "#080e1c", bg2: "#0b1424",

  // 轴心：高饱和警示红
  red: "#e6152b", redHot: "#ff2f42",
  redFill: "rgba(190,18,38,0.62)", redDeep: "rgba(112,8,22,0.55)",
  redEdge: "rgba(255,60,76,0.95)",

  // 同盟：蓝 + 黄 + 金
  blue: "#2f6fd8", blueHot: "#5fa6ff",
  blueFill: "rgba(38,92,190,0.55)", blueEdge: "rgba(120,180,255,0.95)",
  yellow: "#f2c62c", gold: "#d9a63a", goldSoft: "#f0cf7a",

  white: "#ffffff", ink: "#e8eef8",
  dim: "rgba(214,226,244,0.55)", faint: "rgba(190,206,230,0.28)",

  // 陆地/海：这个对比度是全片的地基。land 再暗一档（#141d30）在暗场里就分不出海陆，

  land: "#35486b", landLine: "rgba(168,206,255,0.62)", sea: "#04070e",
```

## 二、占领区：只有两种合法模式，别骑墙

先说结论：**要么"实色版图"，要么"发光轮廓"，中间那一档最难看成片。**

### 模式 A：实色版图（系列片、有先例时优先）

E1 / E2 走的是这条。填色接近不透明、颜色饱和，色块本身就是信息：

```ts
export const FILL_RGB = {           // 存不透明色
  rome:  "rgb(180,26,38)",
  carth: "rgb(34,74,140)",
  greek: "rgb(146,112,44)",         // 别用鲜金，压成青铜色才像古代
};
export const FILL_A = { rome: 0.88, carth: 0.84, greek: 0.66 };
```

边界走"画边 → 用自家填色擦掉内侧 → 只留并集外沿"，三层叠加：

| 层 | 线宽（屏幕像素） | alpha |
|---|---|---|
| 外晕 | 8 / zoom | 0.15 |
| 主边 | 2.6 / zoom | 0.85 |
| 白芯 | 1.0 / zoom | 0.28 |

### 模式 B：发光轮廓（参考片那种"军事推演"味）

填色压到 0.14~0.26，几乎看不见，靠边缘发光读归属。**前提是陆地够暗**（`rgb(20,30,50)` 以下）——陆地一亮，淡填色就和陆地混成一片"发白的紫"，既读不出归属也不好看。E2 第一版就是这么砸的。

```ts
export const SIDE_FILL = {
  axis:    "rgba(198,26,44,0.14)",
  allies:  "rgba(40,96,176,0.14)",
  neutral: "rgba(16,24,40,0.55)",
  gone:    "rgba(30,26,24,0.45)",
};
const CORE_AXIS = "rgba(172,12,30,0.26)";
```

### 怎么选

- 上一集已经定稿 → **照抄上一集的填色浓度和陆地数值**（用户对"画风统一"的容忍度是零）。
- 全新系列、想要参考片那种氛围 → 走模式 B，并且把陆地压暗。
- 绝对不要：陆地亮（`rgb(50,70,105)`）+ 填色 0.25 —— 这组合会产生"发白的紫红"，是两次返工的共同原因。

> 判断标准：**把画面缩到 25% 看。模式 A 应该像一张彩色政治地图；模式 B 应该像一张夜视作战图。两种都行，糊成一片红的半透明不行。**

### 手绘区域一定重叠，必须挖洞

见 pitfalls「两块势力区在几何上真的重叠」。一句话：同阵营先并集 → 按优先级 `destination-out` 互相挖洞 → 再填色，否则同一片地会既红又金。

### 边界必须"清晰"：这是可量化的，不是审美

用户给参考图时的原话是「**国家的边界要清晰，像这张图片一样**」。参考图拆开看是一组数值——**暗填色 + 锐利亮线 + 收敛的光晕**，三者缺一就"不清晰"。

| 量 | 参考片实测 | 阈值 | 为什么 |
|---|---|---|---|
| 领土填色（最大通道） | `rgb(76,21,13)` → **76** | **≤ 110** | 填色一亮，边界线就被淹没。实测 164 时线与底比值 1.1，肉眼看不见 |
| 边界线芯 | `rgb(247,123,122)` → **247** | **≥ 235** | 线必须接近"发光"的亮度，不能只是"比填色亮一点" |
| **线/填色亮度比** | 3.2 | **≥ 2.2** | 这一条是判据本体。达不到就是"糊" |
| 线宽（1920 宽下） | 约 6px | **4~6px** | 3px 以下在缩略图尺度读不出来 |
| 外晕半径 / alpha | 约 16px / 很淡 | **8~10px / ≤ 0.16** | 光晕是让线"浮起来"的，不是给填色加一层红雾 |

**三条实现要点，缺一不可**（都踩过）：

1. **填色要"更暗的色 + 更高的浓度"，不是"降 alpha"**。
   陆地底是蓝灰 `rgb(61,83,121)`，alpha 降到 0.5 时，剩下 50% 的底色会把 B 通道抬高 30 点——红色从暗红变**粉紫**，用户一眼看出不对。
   正确做法：`0.88 × rgb(98,19,12)` 叠在底上 ≈ `(93,25,24)`，既暗又暖。

2. **单次 `blur` 的环只有 0.5 alpha，必须叠加**。
   `blur(r)` 再 `destination-out` 本体，得到的是高斯截面的环，峰值只有 0.5——画出来是"雾带"不是"线"。同一张图叠 5 次到 0.97，横截面才接近方波。

3. **边界层必须画在"陆地裁剪"之外**。
   外发光要能**越过海岸线漫到海面上**（参考片就是这样）。如果贴在 `clip(land)` 里面，光一过海岸就被切掉，红色边缘变成刀切的硬边，海面一点光都没有。

### 验证方式：采样，不要用眼睛

肉眼在暗场图上判断"边界清不清楚"极不可靠（skill 里反复栽在这上面）。直接取像素：

```bash
# 边界线芯（取一个已知的边界位置）
ffmpeg -v error -i frame.png -vf "format=rgb24,crop=1:1:X:Y" -frames:v 1 -f rawvideo -pix_fmt rgb24 - | od -An -tu1
# 或扫描一个窗口内的最亮像素
node /tmp/scan.mjs frame.png X Y W H
```

**判据**：线芯 R ≥ 235、填色 R ≤ 110、两者比 ≥ 2.2。三项同时成立才算"清晰"，否则回去调上面三个参数。

### 领土怎么变化：要"推过去"，不要"换上去"

这条是硬要求，不是风格偏好。实现直接抄 `assets/template/src/front-push.ts`。

**一句话原则**：观众应该看到**一条线在移动**，而不是**一块颜色被替换**。

#### 推进的三段式

| 段 | 时长（136BPM，BEAT=0.441s） | 画面上发生什么 |
|---|---|---|
| 起势 | 0.5s ≈ 1 拍 | 锋线从一端亮起（宽晕先出，白芯稍后），旧色仍在 |
| 推进 | 2.0s ≈ 4.5 拍 | 锋线横扫，线两侧严格互补：内侧新色、外侧旧色（浓度 0.46） |
| 落定 | 0.5s ≈ 1 拍 | 锋线淡出，旧色残块继续衰减到 0，边界回落到常规描边 |

总长 `CHANGE_DUR = 3.0s`。**低于 2s 就读不出"移动"，高于 4s 就会让一集显得拖沓。**

#### 四条必须同时满足

1. **一次事件一条线**。同一批变色的地块共用同一条锋线（同圆心、同半径、同起伏函数），否则红蓝之间会出现一条"既红又蓝"的紫带。
2. **线两侧互补**。接收方画 `side=+1`，让出方画 `side=-1`，用的是**同一个** `frontWave(f, t, rad)`。任何一侧单独算，都会错位。
3. **线要有白芯**。只用宽晕时，它在暗场里像一团光斑；加一条 1.15px 的白芯，才读成"边界线"。
4. **缓动用 `easeInOut`**。用 `easeOut` 时 90% 位移发生在头 1/3，观感退化成"啪一下变色"——这正是被用户点出来的那个问题。

#### 什么该慢、什么该快

| 事件性质 | 时长 | 例 |
|---|---|---|
| 决定性征服 / 战役结果 | 3.0s（可到 3.6s） | 达契亚亡国、耶路撒冷陷落、条顿堡丢地 |
| 常规并吞、行政划归 | 2.2~2.6s | 附庸转直辖、行省重划 |
| 多块地连锁变色 | 仍用 3.0s，但**并发**，不要排队 | 一次东征里亚美尼亚+美索不达米亚同时变 |

**最忌"逐块排队变色"**：区域 A 变完 B 变、B 变完 C 变，看起来像加载动画。同一次事件必须并发。

#### 镜头必须配合推进

推进只在**可读机位**（zoom 0.9~1.1）才成立。

- 全图机位（zoom 0.35）下，3 秒推进的位移只有几十像素，观众只觉得"红色稍微动了一下"，钱花了效果没有。
- 所以：**要展示推进，就把镜头推到战区**；全图镜头只用于"结果对比"，不要在它上面做细腻的推进动画。
- 反过来，插图镜（版画）里不要有推进——插图是"那一刻"的静帧，地图的变动应该在插图出现**之前或之后**完成。


## 三、质感：自发光屏，不是胶片

三个动作，全部在屏幕空间做（`resetT` 之后）：

1. **背景径向渐变**——中心略亮，边缘落到 `#03050a`。
2. **暗角**（`drawVignette`）——只压边缘，保留中心亮度，系数 0.5。
3. **扫描网线**（`drawScanlines`）——4×4 pattern，每 4 行一条 `rgba(120,170,240,0.055)`，系数 0.5。

**不要加颗粒（noise）、不要加径向模糊、不要做景深。** 这是"屏幕"质感，不是"胶片"质感。

## 四、边界发光：宽描边代替 shadowBlur

`shadowBlur` 在 1080p 全屏路径上是性能杀手。用双层描边做出同样的发光感：

```ts
ctx.shadowBlur = 0;
ctx.lineWidth = 5.5 / cam.zoom;   // 外层：低透明度宽描边当光晕
ctx.globalAlpha = 0.30;
ctx.stroke(path);
ctx.lineWidth = 1.6 / cam.zoom;   // 内层：实线
ctx.globalAlpha = 0.95;
ctx.stroke(path);
```

视觉效果与 `shadowBlur` 几乎一致，但速度快一个量级。箭头的外发光同理（`lineWidth = w * 0.55`，`alpha = 0.22`）。

## 五、三层文字，全部承载信息

没有旁白，信息全靠文字。三层各司其职，位置固定：

| 位置 | 元素 | 规格 |
|---|---|---|
| 左上 x=82, y=96 | 红色竖条 (6×38) + 小节标签 17px + 日期 40px/700 | 日期随剧情逐条推进，`fontVariantNumeric: tabular-nums` 防止数字跳动 |
| 左下 x=82, y=H-92 | 红色竖线 (5×52) + 事件 44px/700 + 左侧渐隐底衬 | 底衬用 `destination-over` 铺在文字下面 |
| 中央 y=H×0.47 | 巨大标题 176–210px/900 + 红色矩形框 | 见下节 |

右上角坐标读数（`LON .. LAT .. SCALE ..%`，15px）和底部进度条是"仪表盘"细节，加分会加，但不要做得抢眼。

**所有 HUD 函数必须在开头 `resetT(ctx)`**——地图层改过变换矩阵，不重置的话文字会被带到屏幕外。

## 六、标题：白字 + 贴合红框

```ts
// 弹出
const k = overshoot(clamp01(p / 0.55), 1.9);
const sc = 0.62 + 0.38 * k;          // 从 62% 弹到 100%，过冲到约 108% 再回落
const flash = Math.max(0, 1 - p / 0.22);  // 前 22% 叠一层白闪

// 红框：贴合文字，宽度从 0 展开
const padX = size * 0.26, padY = size * 0.26;
const bw = tw + padX * 2, bh = size + padY * 2;
const w = bw * easeOutQuint(clamp01((p - 0.06) / 0.3));

// 副标题：必须在框外，否则压住框线、和阴影糊在一起
tracked(ctx, sub, 0, size * (box ? 1.1 : 0.95), 8, "center");
```

副标题额外加 `shadowColor: "rgba(2,4,10,0.9)" / shadowBlur: 16` 提可读性。`size*0.95` 是踩过的坑：副字会正好坐在框底边上。

## 七、运镜：分级不动（不是全程不动）

**单镜之内机位绝对静止**——这一条没得商量，镜内一推拉就变成纪录片。但**换镜时可以跳档**，而且应该跳：

| 档 | zoom | 用途 |
|---|---|---|
| 战略 | 1.0 ~ 1.6 | 全景态势、阵营对比、终局 |
| 战役 | 2.2 ~ 5 | 一次战役的地理范围，能看清海岸与岛屿 |
| 战术 | 8 ~ 24 | 单个城市、海峡、翻山路线；地图信息已不够，切示意图 |

节奏上按 **战略 → 战役 → 战术 → 战略** 走，像镜头语言里的"全景—中景—特写—全景"。E1 实测：七丘那一镜用 22 倍，用 7 倍时七个山丘挤成一点，完全读不出来。

镜内所有动感来自画面内部：

- **占领区蔓延**：`fillGrow()` 沿方向向量做波前推进，用半平面裁切，不要用渐变遮罩（渐变会糊边）
- **进军路线延伸**：`drawArrow()` 按 `prog` 逐步 `cut()` 折线
- **标记弹出**：`overshoot` 过冲
- **航线流动**：`lineDashOffset` 递减
- **转场**：0.055s 压黑（不是淡入淡出叠化，是一瞬间的黑闪）

> 早期版本写的是"全程固定机位、禁止推拉摇移"。那是把"镜内不能动"误升级成了"全片不能换档"。实测下来，全程一个 zoom 的片子在第 40 秒就失去注意力——观众需要"凑近看"这个动作来理解重要性。**换镜跳档 ≠ 推拉摇移。**


## 八、其他约定

- 标题镜（title）用纯地图打底 + 极淡暗角，不放任何箭头标记，让标题独占画面。
- 爆炸用全屏白闪（`p < 0.11`）+ 6 段径向渐变火球 + 4 层冲击波环 + 34 条放射线（带 jitter）。不要只画一个橙色圆。
- 城市战术图（city）用**屏幕尺度**的 52px 街区网格 + 贝塞尔河流 + 包围环，不要用地图坐标画网格。
- 终局金色：**先用暖色陆地打底，再叠金色**。直接在深蓝陆地上叠金色会混成浊褐。
