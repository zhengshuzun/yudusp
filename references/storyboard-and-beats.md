# 分镜与卡点

## 一、镜头类型

只有五种，够用了。每种对应 `render.ts` 里的一批 case：

| kind | 用途 | 画面 |
|---|---|---|
| `map`（默认） | 主叙事 | 地图 + 占领区蔓延 + 进军箭头 + 城市点 |
| `title` | 章节转场 | 纯地图打底 + 中央巨大标题弹出 |
| `cards` | 阵营介绍 | 4 张国名卡片快切（每张 0.8–0.9s） |
| `city` | 单场战役 | 城市战术图：街区网格 + 河流 + 包围环 + 部队光点 |
| `boom` | 高潮 | 全屏爆炸 + 白色说明文字 |
| `finale` | 终局 | 金色定格 + 淡出 |

## 二、镜头表的写法

```ts
const S = (id, t0, t1, lon, lat, zoom, dates, event?, extra = {}) => ({
  id, t0, t1, cam: camAt(lon, lat, zoom), dates, event, ...extra,
});

export const SHOTS: Shot[] = [
  S(2, 2.17, 9.23, 19.5, 52.2, 1.02,
    [{ t: 2.17, text: "1939.9.1" },
     { t: 4.20, text: "1939.9.17" },
     { t: 6.40, text: "1939.9.27" }],
    "德苏瓜分波兰",
    { kicker: "闪 击 · 波 兰" }),
  ...
];
```

字段含义：

- `lon/lat/zoom`：固定机位。`zoom = 1.0` 大约覆盖 19° 经度；`0.4` 覆盖全欧；`4~9` 是城市战术图。
- `dates`：左上角日期的推进序列，**每条必须落在拍点上**，间隔 2–4 拍。`t: -99` 表示"从第一帧就在"。
- `event`：左下角事件文字。标题镜留空。
- `kicker`：左上角小节标签，中文用空格隔开做字距（`"闪 击 · 波 兰"`）。
- `title`：仅 title 镜使用，`{ main, sub?, color?, size?, box?, y? }`。

## 三、节奏分配（关键）

一个 150s 的片子，25 个镜头，实测好用的结构：

- **普通地图镜 5–14s**，夹在标题镜之间
- **标题镜 1.7–2.8s**（4–6 拍），只放标题，不解释
- **快切镜（cards）4–5s**，内含 4×0.85s 子镜
- **高潮镜（boom）1.8s**，全片最短之一
- **终局镜 8–9s**，留足淡出

标题镜的间距要**越来越密**：前半段 20s 一个，后半段 10s 一个。观众越看越快，节奏跟着收。

这部片子的五个标题镜落点（也是必须对齐重低音的五个帧）：

| 镜 | 时间 | 内容 | 为何在这 |
|---|---|---|---|
| 6 | 27.76 | 1941 / 巴巴罗萨 | 第一幕的中点，全片第一个大转折 |
| 11 | 64.82 | 转折点 | 全曲 breakdown 结束、第二次 drop 前 |
| 15 | 84.23 | 1943 / 攻守易势 | 中段翻盘的宣言 |
| 17 | 94.82 | D-Day | 西线开辟，最有符号意义的词 |
| 22 | 127.46 | （爆炸） | 全曲最响处，希特勒之死 |

## 四、卡点公式

节拍网格来自 `beatmap.json`：`t = phase + k × beat`。

```ts
export const beatGrid = { bpm: 136, phase: 0.4058823529411764 };
export const BEAT = 60 / beatGrid.bpm;
export const beatTime = (k: number) => beatGrid.phase + k * BEAT;
```

算切点的方法：先定"这一镜大概多长"，再把它**吸附到最近的拍**上。

```python
BEAT, PH = 60/136, 0.40588
def snap(t):            # 把秒吸附到最近拍点
    k = round((t - PH) / BEAT)
    return PH + k * BEAT, k
```

核对方式：`(t - (PH + k*BEAT)) * 1000` 应当在 ±10ms 内。30fps 下 1 帧 = 33ms，±10ms 已经是 1/3 帧以内。

**标题弹出帧还要额外对齐重低音**。做法是在 `beatmap.json` 的 `top`（最强 40 个低音点）里找离目标时间最近的那个，但通常「拍点」和「低音点」是重合的——只要切点严格落在拍格上，重低音自然到位。

```json
    { "t": 45.40,  "fx": "tick",   "args": { "dur": 0.1, "gain": 0.9, "f": 2100 }, "gain": 0.7 },
    { "t": 96.58,  "fx": "whoosh", "args": { "dur": 1.2, "gain": 0.6 } },
    { "t": 122.20, "fx": "riser",  "args": { "dur": 5.2, "gain": 0.62 } },
    { "t": 127.46, "fx": "boom",   "args": { "dur": 3.0 }, "gain": 1.15 },
    { "t": 127.46, "fx": "impact", "args": { "dur": 1.9, "f0": 210, "f1": 24, "noise": 0.8 } },

  ]

```

### 音乐刹车

`brakes` 是在大标题砸下来之前把音乐"吸住"的手法：用 1.1s 把低通从 18kHz 压到 240Hz、音量降到 13%，标题落地后再用 0.55s 放开。听感上是音乐突然闷住，然后标题带着 impact 砸进来。**只给全片最重要的那个标题用，用多了就废了。**

### 音效落点规则

- 每个 `title` 镜的 `t0` → `impact`，基频按重要性递减（165 → 190 → 175 → 200 Hz），越重要的标题基频越高、衰减越长
- `boom` 镜 → `boom` + `impact` 双层叠
- `cards` 每个子镜 → `tick`，基频逐张 +220Hz
- 地图镜开场 / 大规模推进 → `whoosh`
- 高潮前 5s → `riser`，长度正好顶到高潮

### 软限幅

叠加多层音效后峰值常常超出。`limit: 31000`（≈ -0.5dBFS）留一点余量，比硬削波好听。

## 六、镜9 这类"四连快切"的写法

一个镜头里放 4 个子镜，每个 0.85–0.9s，**每个子镜的起点也要落在拍上**（136BPM 下 2 拍 = 0.882s）：

```
45.40 → 46.28 → 47.16 → 48.05   （每张间隔 0.88s ≈ 2 拍）
```

`render.ts` 里按 `(t - s.t0) / 0.88` 取整决定画第几张，`tick` 音效同步落在同样的四个时间点。
